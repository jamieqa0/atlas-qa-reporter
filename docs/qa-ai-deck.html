📝 기획서(Figma) 캡처 → 요구사항 구조화

Figma 기획서 캡처를 공유 → OCR로 텍스트 추출 후 요구사항까지 구조화. 불확실한 부분은 스스로 교정하고 TBD도 명확히 구분해줍니다.

# Figma 캡처 → OCR → 구조화 DB 공급 설정 ├─ 전국 + 수량 케이스 │ ├─ 총 계약 수량 등록 (예: 5,000건) │ └─ 미보장담보 체크 시 입력 활성화 ├─ 고객사 노출 메시지 │ └─ "암진단 미보장" 등 문구 입력 └─ 중복 등록 가능 (정책) ⚠ TBD: 권역별·기간별 설정은 추가 기획서 확인 필요
🔑

모른다고 말하는 게 좋은 AI: AI가 "나머지 3개 공급방식은 추가 기획서가 있어야 정확히 작성할 수 있습니다"라며 스스로 범위를 구분해줬어요. 억지로 채우지 않고 TBD를 남기는 게 핵심이에요.

📱 앱 화면 캡처 → 기능 유추

보닥 앱 스크린샷 하나만 줬더니, 기획서 없이 AI가 테스트할 기능을 스스로 읽어냈어요.

# 스크린샷 1장 → AI 기능 유추 종합진단 점수 영역 → 점수 계산 로직, 등급 표시 정확성 보험료 합산 표시 → 합산 오류, 갱신 시 금액 반영 알림 · 상담 버튼 → 미읽음 배지, 딥링크 이동 하단 네비게이션 → 탭 전환, 선택 상태 하이라이트
STEP 1 요건 분석 · 🔎 파헤치기

정보가 부족한 개발 건 → AI가 흩어진 맥락을 모아줌

"SDK 업그레이드"처럼 티켓 한 줄로는 뭘 테스트할지 막막한 개발 개선 건. 사람한테 물어봐도 정보가 부족할 때, Rovo에게 던졌더니 Jira 에픽·Confluence 주간보고·과거 QA 기록을 직접 뒤져서 정리해줬어요.

💬 실제로 쓴 프롬프트

"APTS-772가 무슨 작업이고, 앱 어디에 영향이 있고, 뭘 테스트해야 하는지 정리해줘."

티켓 번호 하나만 던졌는데, 사람에게 물어도 안 나오던 맥락을 흩어진 문서에서 스스로 모아 왔어요.

# 무슨 작업? Expo SDK 55 · RN 0.83 업그레이드 — Expo 마이그레이션 Phase 3 # 앱 영향 범위 (과거 이슈가 단서) 건강연동(Coocon) · 보안모듈(Raon) · 모달/바텀시트 WebView 크래시 · PDF 다운로드 · OTA(EAS Update) # 테스트 관점 제안 네이티브·보안 최우선 → UI 렌더링 → 핵심 플로우 → iOS/Android 차별 → 성능·안정성 ⚠ 근거: 4.7.0 RN QA 때 Full TC로 25건 이슈 발생 전례
🔑

흩어진 맥락을 모아주는 게 핵심: 사람한테 물어도 "글쎄…"였던 걸, AI가 Jira 에픽 + Confluence 주간보고 + 과거 QA 기록까지 교차 조회해서 영향 범위와 테스트 관점까지 엮어줬어요. 물론 최종 테스트 범위 판단은 QA의 몫이고요.

+ AI 상담사(챗봇) 특화 TC도 AI가 설계

기능 TC를 넘어, LLM 챗봇만의 고유 리스크까지 AI가 17종(+ETC)으로 설계해줬어요. 보험 도메인 지식 + AI 안전성을 함께 검증합니다.

QA라면 매일 쓰는 포맷인데, AI에게 상황만 설명하면 깔끔하게 뽑아줍니다.

💬 실제로 쓴 프롬프트

"이 내용을 [Title][Step][Actual Result][Expected Result] 형식으로 잘 정리해서 다시 써줘."

구어체로 현상만 설명해도 구조화된 이슈 문장으로 바꿔줍니다. 환경 정보(디바이스·OS·앱 버전)도 함께 넣어달라고 하면 완성도가 올라가요.

❌ Before — 머릿속 메모

"보상 문의하기에서 글 쓸 때 키패드 올라오면 글자 수 표시가 안 보임. 이전 버전에선 됐는데..."

"스크롤이 좌측으로 이동되었고, 좌우 여백이 커졌어. 이전 버전에선 안그랬는데..."

✅ After — AI가 다듬은 결과 + QA 최종 검토 (중요!!)
[Title] [보상] 문의하기 작성 중 키패드 노출 시 실시간 글자 수 체크 영역 미노출 [Step] 1. [보상] 보상 문의하기 게시판 내용 작성 [Actual Result] • 내용 작성 중 실시간 글자 수 체크 영역이 키패드 상단에 노출되지 않음 • 완료 버튼 선택 후 키패드가 내려간 이후에야 글자 수 체크 영역이 노출됨 • 4.9.10에서는 정상 노출됨 [Expected Result] • 키패드 노출 시에도 실시간 글자 수 체크 영역이 입력창 상단에 정상 노출되어야 함 • 상세 레이아웃은 Figma 화면정의서 참조

"내 최근 이슈 기반으로 발표 자료 만들어줘"라고 했더니 Rovo가 Jira를 직접 조회해서 실제 이슈를 가져왔습니다. 복붙 없이요.

APTS-781 보상 문의하기 — 키패드 올라올 때 글자수 체크 미노출 APTS-782 보상 문의하기 — 글자수 오류 메시지 위치 우측으로 치우침 APTS-784 공동인증서 관리 — 클락 애니메이션 미노출 → 이슈들의 Step/AR/ER 구조를 분석해서 발표 Before/After 사례로 바로 활용
📊 ChatGPT vs Claude vs Rovo — 어떻게 나눠 쓰나? ▼

ChatGPT: 범용 작업에 강함 — OCR, 외부 자료 정리, 일반적인 글쓰기, 빠른 브레인스토밍
Claude: 길고 복잡한 맥락을 다룰 때 — 여러 화면/대화를 종합해서 구조를 짜야 하는 작업, 문서나 발표자료처럼 단계별로 다듬어가야 하는 작업 (이 발표 구조도 Claude와 함께 정리했어요)
Rovo: Atlassian 생태계에 특화 — Jira/Confluence 데이터 참조, 페이지 생성, 워크플로우 안에서 바로 실행

셋 다 "글을 대신 써주는 도구"가 아니라, "초안을 빠르게 만들어주는 파트너"로 쓰고 있어요.

wrap-up — 가장 중요한 것

딱 하나만 기억한다면, 검증은 반드시 직접

⚠️ AI는 "그럴듯한 거짓말"을 잘 합니다

AI가 만든 TC·이슈 문장·보고서 초안은 반드시 사람이 최종 검토해야 합니다. 도메인(보상·미보장담보 등)을 아는 QA의 눈으로 사실을 확인하는 것 — 그건 줄지 않는, 줄여서도 안 되는 시간이에요. TBD라고 "모르겠다"고 말하는 AI가 오히려 믿을 만한 AI입니다.

⚖️

생산성이 높아진 만큼, 검증할 거리도 많아집니다. 초안을 빨리 받는 만큼 "이게 맞나?"를 따져볼 양도 늘어요 — 아낀 시간은 결국 더 꼼꼼히 보는 데 다시 씁니다.

🪙

QA는 의외로 'AI 토큰'을 많이 씁니다. 문서 작업, 엣지 케이스·리스크 탐색, 오류 디버깅·수정, 회귀 테스트까지 — 드러나는 버그 리포팅은 빙산의 일각일 뿐이에요. AI에 기대다 보니 이 일들이 겉으로 드러나지 않을 뿐 얼마나 많고 고된지 새삼 알게 됐고, 결국 품질은 비용이라는 걸 다시 느낍니다.
